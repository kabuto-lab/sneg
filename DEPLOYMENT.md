# Выкладка и домены

Исходники: https://github.com/kabuto-lab/sneg. Основной адрес:
https://snegurochkimoscow.com. Домены `snegurochkimoscow.ru`,
`www.snegurochkimoscow.ru` и `www.snegurochkimoscow.com` перенаправляются на него
с кодом 301, сохраняя путь и параметры. Проверка Let's Encrypt обслуживается
отдельно для продления действующего сертификата. Файлы `yandex_*.html` для `.com`
также обслуживаются напрямую по HTTP и HTTPS, включая `www`, из
`/var/www/verify/snegurochkimoscow.com`. Для этих файлов требуется ответ 200
без перенаправления; остальные страницы следуют обычным правилам редиректа.

За основу взята рабочая версия `7412b4164d8f7432bcbe0494b80f2c86486f435f`
из `meremarina51-ctrl/snegurochka`. История Git сохранена, включая три исправления,
которых не было в прежней ветке `main`.

## Разработка

Нужны Node.js 22 и Corepack. Версия Yarn закреплена в `package.json`.
Production-сборка использует Webpack: исходная команда Turbopack в Next.js 16.3.6
падала при обработке `next/font/google` для Cormorant Garamond на VPS.

```powershell
corepack yarn install --frozen-lockfile
corepack yarn dev
```

Тексты и переводы: `src/lib/i18n/translations.ts`. Пути к изображениям и
дополнительные цены: `src/components/constants.ts`. Изображения: `public/`.
Лендинг сам по себе не загружает анкеты или смены из CRM. Локальный прототип
с запотевшим стеклом и шарами в этот репозиторий не включён.

## Выкладка на Zomro

После коммита и отправки изменений в `main`:

```powershell
git push origin main
.\ops\deploy.ps1
```

Это явная выкладка, а не автоматическое действие при каждом `git push`.
Нужен существующий SSH-доступ через псевдоним `zomro`. Пароли, токены и ключи
в репозиторий не передаются. Можно указать другой SSH-псевдоним:
`.\ops\deploy.ps1 -Server my-vps`.

Скрипт берёт только уже отправленный коммит из `origin/main`, собирает его
в отдельном каталоге, проверяет на временном локальном порту и переключает
службу после успешной проверки. При ошибке запуска возвращает прежний релиз.

На VPS:

- `/opt/sneg/repository` — копия нового GitHub-репозитория;
- `/opt/sneg/releases/<commit>` — отдельные сборки;
- `/opt/sneg/current` — текущая сборка;
- `/opt/sneg/backups` — сохранённые конфигурации и сведения для отката;
- служба `snegurochka-next.service`, локальный порт `5134`.

Настройки доменов хранятся в `ops/nginx/`. Их применение — отдельная операция:
`python3 /opt/sneg/current/ops/activate-domains.py` на VPS. Скрипт сохраняет
предыдущие файлы, проверяет `nginx -t`, ответы доменов и точное содержимое файлов
Яндекса по обоим протоколам и откатывает конфигурацию при ошибке.
Обычная выкладка приложения настройки nginx не переписывает.

При точечном исправлении nginx операционные файлы `ops/` могут обновляться из
Git без пересборки приложения, с резервной копией. В таком случае
`/opt/sneg/current/CONFIG_COMMIT` хранит коммит настроек, а `RELEASE_COMMIT` —
коммит приложения. При обычной полной выкладке оба набора берутся из одного коммита.

Прежнее приложение в `/opt/ext-snegurochka` и старый PHP-сайт `.com`
в `/opt/sites/snegurochkimoscow` сохраняются как исходные копии.

## Проверка

```powershell
corepack yarn lint
corepack yarn build
```

Форма `/vacancies` в унаследованном коде записывает заявку только в журнал
приложения; внешняя доставка заявок здесь не настроена.
